# 예제 PABI-01 · 파비 첫 연결과 첫 사용

DASONI Android의 기기 연결 흐름을 참고한 AGENT-STUDY 팀 테스트다. 장면과 구현 후보는 테스트 입력이며, 모든 역할은 이 문서의 가정을 기준으로 결과를 작성한다.

## 입력

- 사용자 상황: 처음 파비를 연결하거나 연결 도중 문제가 생겼다.
- 현재 흐름: 앱에서 Bluetooth로 기기를 검색하고, Wi-Fi 설정을 전달한 뒤 기기 응답을 확인한다.
- 설계 후보: ‘파비의 공간’에서 기존 연결 화면을 열고, 설정 결과에서 첫 사용 가이드로 이어진다.
- 자료 상태: 실물 기기 확인 기록과 새 저장 정책의 승인 근거는 제공되지 않았다.

## 기대 결과

| 케이스 | 역할과 테스트 입력 | 기대 결과 |
|---|---|---|
| PABI-01-A | PM에게 기존 연결 화면과 첫 사용 가이드 후보를 준다. | 기존 흐름을 재사용하는 구현 예시, 담당 역할, 검수 순서를 작성한다. |
| PABI-01-B | 제작자에게 미발견·설정 실패·설정 응답 세 상황을 준다. | 상황마다 다른 안내와 다음 버튼을 제시한다. |
| PABI-01-C | QA에게 설정 응답만 보이고 공유기 접속 증거가 없는 화면을 준다. | 응답 확인과 실제 접속을 구분하고 실기기 확인을 체크리스트에 남긴다. |
| PABI-01-D | QA에게 Wi-Fi 비밀번호 보관 방식이 서로 다른 두 가정 문서를 준다. | 충돌을 발견해 PM에 전달하고, PM은 승인 근거가 필요한 항목으로 기록한다. |
| PABI-01-E | 같은 업무 ID로 예제를 두 번 접수한다. | 테스트 보드에 동일 키로 접수하고 카드는 수동 검토 대기로 시작한다. |

### 역할별 고정 입력

- 기기 미발견은 전원이 켜져 있는지 확인하고 다시 검색할 수 있다.
- 설정 실패는 Wi-Fi 정보를 확인하고 다시 입력할 수 있다.
- 설정 응답을 받았을 때는 실제 접속을 기기 안내음이나 공유기에서 확인한다.
- 저장 정책 가정 A는 연결 세션의 메모리에만 비밀번호를 둔다. 가정 B는 휴대전화에 암호화해 보관한다. 승인된 정책은 입력에 없다.

팀의 역할 분담과 QA 판단이 검증 대상이다. 실기기·배포 상태는 이 예제에서 확인 대기로 기록한다.
