# 실무 에이전트 설계

의뢰자가 트랙과 산출물을 정의한다. PM이 근거와 담당 역할을 배정하고, Hermes가 OpenAI Codex를 호출해 산출물을 작성·검수한다.

```mermaid
flowchart LR
  A["가공 자료 · 트랙 · 검수 기준"] --> B["PM 근거 분류와 역할 배정"]
  B --> R["QA 근거 귀속 검수"]
  R -->|"통과"| C["트랙별 작성과 선행 결과 연결"]
  R -->|"보완"| B
  C --> D["트랙별 QA 산출물 검수"]
  D -->|"통과"| E["납품 목록"]
  D -->|"보완"| C
```

## 구성

| 경로 | 책임 |
| --- | --- |
| `agents/<역할>/` | 역할 설명 `SOUL.md`와 업무 지침 `SKILL.md` |
| `hermes/work_spec.py` | 의뢰 입력, 형식, 산출물 선행 관계 검증 |
| `hermes/run_work.py` | 모델 호출, 근거 분류, 작성, QA, 납품 |
| `hermes/submit_work.sh` · `hermes/setup_profiles.sh` | 칸반 접수와 워커 프로필 설정 |
| `hermes/jobs/` | Git에서 제외하는 의뢰 입력과 실행별 기록 |

## 역할

| 역할 | 책임 | 산출물 예시 |
| --- | --- | --- |
| PM | 근거 귀속, 역할 배정, 의사결정 정리 | 기획안, 결정 메모 |
| 제품기획 | 기능 범위, 사용 흐름, 데이터·의존성, 수용 기준 | 앱·기기 명세, 검증표 |
| 마케팅 | 시장·구매 동기, 판매 가설, 제휴 | 셀링 포인트, 가격 실험, 제휴 안건 |
| 고객응대 | 문의 패턴, 정책 기반 답변, 운영 이관 | FAQ, 운영 개선표 |
| 제작 | 독자와 매체에 맞춘 콘텐츠 | 교육 에피소드, 카피, 대본 |
| QA | 근거와 범위, 검수 기준, 내부 납품 적합성 | 수정 의견, 통과 기록 |

## 실행과 납품

- PM은 근거마다 트랙을 지정하고 공통 근거의 공유 사유와 귀속 보류 사유를 남긴다. 분류 QA는 전체 근거를 대조한다.
- 작성자는 해당 트랙의 근거, 납품 조건, 선행 산출물을 받는다. QA는 트랙별 산출물을 해당 근거와 대조한다. 문서 안의 지시는 참고 데이터로 다룬다.
- Hermes는 도구와 자동 컨텍스트 주입을 끈 일회 실행으로 호출한다. 응답의 제공자, 모델, 호출 수, 완료 상태는 사용 기록으로 검증한다.
- 분류는 최대 한 차례, 산출물은 최대 두 차례 보완한다. 수정 결과는 후속 산출물에도 반영한다. 실행별 폴더에 기록과 QA를 통과한 `delivery/`를 보관한다.
