# 아리랑TV 협업 굿즈 파비: 앱·실물 MVP 기능 명세

## 범위와 사용자 장면

확인된 내부 결정: 이 명세는 아리랑TV 협업 실물 굿즈 사업을 다룬다. K-pop 연계 한국어 교육 사업과 목표·납품을 분리한다. [two-projects]

미확정: 실제 배송 제품, 앱·기기 연결 방식, 협업 자료 제공 및 이용 권한은 확인되지 않았다. 따라서 아래는 출시 확정 사양이 아니라 개발·운영 검증을 위한 제안이다. [goods-app-first][partner-data]

대상 사용자 가설은 해외에서 관심 아티스트의 방송·컴백 일정을 챙기고, 활동 후 간단한 기록을 남기려는 팬이다. 캘린더와 기존 알림 계정이 대체 수단이다. 파비가 검증할 차이는 관심사 설정부터 현지 시각 알림, 활동 기록, 다음 일정 확인까지 이어지는 주간 흐름이다. 매주 다시 쓸 이유가 확인되지 않으면 기기 구매 이유나 월 구독 이유로 확대 해석하지 않는다. [goods-app-first][goods-weekly]

| 단계 | 첫 사용과 주간 루프 제안 | 앱 단독 대안과 기기 추가 효용 |
|---|---|---|
| 앱 선행 | 첫 사용: 관심사·시간대·알림 수신 여부 설정 → 출처와 갱신 시각이 표시된 일정 확인. 주간: 일정 전 알림 → 일정 변경·취소 확인 → 활동 후 짧은 기록 → 다음 일정 확인. | 앱 알림과 화면 기록만으로 반복 사용을 검증한다. 협업 자료가 없어도 공식 소스 링크와 자작 문구로 시험한다. [goods-app-first][goods-weekly][rights] |
| 기기 추가 | 앱 흐름이 성립한 뒤, 사용자가 선택한 알림을 가까이 놓인 실물에서 확인하는 흐름을 시험한다. | 손을 쓰지 않는 알림 확인과 소장성이 추가 가치 가설이다. 앱으로도 같은 정보를 확인할 수 있으므로 기기만의 구매 가치는 별도로 검증한다. 기기 대화·연결 구현은 확정되지 않았다. [goods-app-first] |

## 우선순위별 기능과 수용 기준

| 우선순위·기능 | 처리 위치 | 입력과 성공 기준 | 실패·재시도 및 제약 |

| P0 일정 등록·출처 관리 | 운영자·서버·앱 화면 | 운영자가 공개 일정의 원문 URL, 행사명, 원문 시간·시간대, 확인·갱신 시각, 상태를 등록한다. 앱에는 출처 링크와 마지막 확인 시각이 보인다. | 출처 또는 시간대가 불명확하면 자동 알림 대상으로 게시하지 않는다. 운영자는 변경·취소를 반영하고, 이미 알림이 나간 건의 정정 필요 여부를 확인한다. 데이터 제공·갱신 조건이 합의되지 않은 협업 자료는 넣지 않는다. [goods-weekly][partner-data] |

데이터 운영 제안: 앱형 시험은 출처를 확인할 수 있는 공개 일정 링크와 운영자가 작성한 문구로 제한한다. 수집 항목은 관심사, 시간대, 알림 동의·설정, 활동 기록, 발송·오류 확인에 필요한 최소 로그로 정의한다. 수신 동의 철회, 기록 삭제, 계정 종료 시 서버·연결 기기·백업에 각각 무엇이 남는지 시험 전에 명시하고 삭제 동작을 검증한다. 공개 안내를 이용하는 것과 방송·음성·독점 자료의 재사용 권한은 별개다. [rights][partner-data][public-show]

## 첫 버전 제외 범위와 착수 의존성

첫 버전에서는 실시간 방송 소리 분석·공식 라이브 서버 수신·시청 지연 동기화, 방송 영상·음성 재사용, 실존 아티스트 음성 합성, 질문지·백스테이지 답변 해금, 유료 투표 혜택을 제외한다. 방송 처리·제공 권한과 동기화 성능, 답변지 제공·정정 조건, 녹음 재생 권한과 합성 권한, 투표의 제공·유료 배정 권한이 각각 미확인이다. 공식 방송 페이지의 투표 경로는 파비의 투표 연동 권한을 뜻하지 않는다. [goods-live][goods-exclusive][goods-voting][public-show][partner-data]

일정을 잡기 전 확인할 의존성과 다음 판단은 다음과 같다.

1. 콘텐츠 운영: 공개 일정의 담당 출처, 확인 주기, 변경·취소 감지 방법, 오보 정정 책임을 정하고 실제 변경 사례로 운영 절차를 시험한다. 유지할 수 없다면 자동 리마인드 범위를 줄이고 출처 링크 중심으로 시험한다. [goods-weekly][partner-data]
2. 앱·서버: 시간대·서머타임 경계, 알림 동의 철회, 방해금지, 중복 발송, 오프라인 동기화, 기록 삭제를 테스트한다. 실패한 항목은 해당 기능의 배포 조건에서 제외하거나 수동 운영 범위를 명시한다. [goods-app-first][goods-weekly]
3. 기기: 시제품의 연결·해제, 전달 지연, 전원·네트워크 단절, 양도 시 데이터 삭제를 앱 단독안과 비교 시험한다. 성공 전에는 기기 기능이나 배송 일정을 약속하지 않는다. [goods-app-first]
4. 권리·협업: 자료별 제공 여부, 지역·기간·용도, 갱신·철회 절차를 확인한다. 승인된 녹음의 재생과 음성 합성은 별도 항목으로 판단한다. 확인 전에는 실시간 방송·음성·투표를 개발·판매 범위에 넣지 않는다. [partner-data][goods-exclusive][goods-live][goods-voting][rights]

## 행동 검증과 다음 결정

다음 수치와 기간은 실험 설계 제안이며 관찰 결과가 아니다. 착수 전에 모집 경로, 표본 목표, 성공·중단 기준을 확정한다.

| 검증 | 행동 지표·분모·관찰 기간 | 다음 결정 |
|---|---|---|
| 앱 주간 루프 | 첫 관심사를 설정한 사용자 중 다음 주에 앱으로 돌아와 일정 확인 또는 활동 기록을 한 비율. 첫 설정 후 2주 관찰하며 유입 경로별 분모와 인원을 함께 보고한다. | 재방문과 알림 수신 동의·철회 양상을 보고 알림 중심·기록 중심 흐름 중 유지할 안을 고른다. 반복 사용이 확인되지 않으면 기기·구독 기능을 늘리지 않는다. [goods-weekly] |
| 기기 추가 가치 | 앱을 체험한 뒤 각 안의 제공 범위와 가격 후보를 본 사람을 분모로, 앱 단독안 대비 실물안의 구매 단계 진입 행동을 비교한다. 2주 시험을 제안한다. 설문 응답은 별도 집계한다. | 결제·환불 수단이 마련되지 않았다면 구매 전환으로 판단하지 않는다. 실물 SKU·원가·배송비·세금과 가격 후보의 관계를 확인한 뒤 실제 판매 시험 여부를 결정한다. [goods-app-first][goods-price][price-conflict] |
