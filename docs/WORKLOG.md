# 작업 과정

## 1. 아이디어
- 처음에는 세 에이전트가 각자 따로 일하는 구조였다.
- 결과물을 보니 서로 넘겨야 할 일이 이미 있었다. PM 칸반의 "블로그 초안"은 마케팅의 일이고, "FAQ 추가"는 클라이언트의 일이며, 클라이언트가 받은 버그 신고는 PM 칸반에 올라가야 했다.
- 그래서 **에이전트끼리 일을 주고받는 팀 구조**로 바꿨다.

## 2. Python으로 먼저 검증
- 프로필 구조(SOUL, SKILL, USER)로 정의 파일을 만들고, Python 실행기로 동작을 확인했다.
- 소통은 출력 끝의 `## HANDOFF` 줄을 실행기가 읽어 다음 에이전트에게 전달하는 방식으로 했다.

## 3. Hermes로 옮기기
- Hermes(v0.23.2)를 설치하고 모델을 Claude Opus 5.5로 설정했다. Hermes 소스에서 Anthropic 제공자와 Claude Pro 구독 로그인이 지원되는 것을 확인했다.
- `agents/`의 정의 파일을 그대로 프로필 3개로 옮겼다. 세 프로필 모두 자기 스킬을 인식했다.
- 처음에는 공유 폴더에 수신함 파일을 두는 방식을 계획했지만, Hermes에 **칸반**이 기본으로 들어 있어서 이것으로 바꿨다. 직접 만든 방식보다 기록, 재시도, 사람 개입을 더 잘 지원한다.
- 오너는 시작 카드 2장만 올리고, 나머지는 PM이 `kanban_create`로 직접 배분하게 했다.

## 4. 문제와 해결
| 문제 | 원인 | 해결 |
|---|---|---|
| Hermes 기본 모델이 claude-opus-4.6 | 설정 기본값 | `setup_profiles.sh`에서 프로필마다 claude-opus-5-5로 설정 |
| Hermes가 USER.md를 읽지 않음 | 프로필 루트에 넣었지만 Hermes는 `memories/USER.md`에서 읽음 | 메모리 형식(항목 사이 `§`)으로 바꿔 `memories/USER.md`에 넣음. PM에게 물어 오너 선호를 아는지 확인 |
| 다시 실행하면 이전 카드와 섞임 | 같은 보드를 계속 사용 | `run_team.sh`가 시작할 때 이전 카드를 보관(archive) 처리 |
| 칸반 기록이 Hermes DB에만 있음 | Hermes 내부 저장 방식 | `export_board.py`로 카드, 요약, handoffs를 Markdown으로 내보냄 |

## 5. 검토
- 문서 링크, 스크립트 문법, 결과 문서의 주장을 실제 결과 파일과 칸반 기록에 하나씩 대조했다.
- USER.md 문제를 고친 뒤 Hermes 팀을 다시 실행해 최종 결과를 만들었다.
